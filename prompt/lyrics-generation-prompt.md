# 周杰伦歌词题生成提示词

```text
你是周杰伦题库编辑。请生成 {数量} 道 `LYRICS`（歌词）题，并输出可直接导入 MySQL 的 SQL 脚本和审核事实卡。

## 任务范围

- `category` 固定为 `LYRICS`。
- 题目考查周杰伦正式发行录音版本中的歌词记忆与歌词辨识。
- 可用题型：短句识曲、下一句、上一句、关键词填空。

## 事实核验与来源

1. 每道题必须先核验，再生成。
2. 优先来源：实体专辑歌词本、数字专辑内页、正版音乐平台歌词页、杰威尔音乐作品/MV/新闻页、发行方或词作者正式物料。
3. 搜索摘要、百科、歌迷站、论坛和短视频只能用于定位来源，不能单独作为依据。
4. 每个事实卡必须记录题号、事实断言、来源 URL、页面标题或署名、版本口径、核验日期和状态。
5. 无法确认版权来源、歌词版本或相邻关系时，不得写入 SQL，改列为“待人工确认”。

## 歌词题规则

1. 只使用完成题目所必需的短歌词；不要连续摘录主歌、副歌或整段歌词。
2. 同一首歌可使用不同歌词线索和题型出多题，但不得复用相同题干、相同短句或高度同义考点。
3. 不使用 Live 改词、翻唱歌词、MV 字幕、非正式 Demo、网友转写或版本不明歌词。
4. 题干不得泄露专辑名、发行年份、作词人等会直接提示正确答案的信息。
5. 4 个选项必须同维度且合理，且只有 1 个正确答案；不要使用玩笑或明显无关选项。
6. 中文歌曲名采用正式中文标题；简繁、英文副标题或标点差异以权威来源页面为准。
7. `album` 填歌曲直接归属的正式专辑；单曲、原声或归属不明确时填 `NULL`。

## 难度与答案分布

总题数为 {数量}，难度目标比例为 `EASY/MEDIUM/HARD = 20/50/30`。

1. 先分别计算三种难度目标数量并向下取整。
2. 将余数分配给小数部分较大的难度；小数部分相同则优先 `MEDIUM`、`HARD`、`EASY`。
3. `EASY` 使用高辨识度代表作；`MEDIUM` 考查非主副歌或同专辑辨别；`HARD` 使用精确相邻句或高相似干扰项。
4. 正确答案 `A/B/C/D` 必须尽量均衡，任两项数量差不超过 1。

## 示例

以下仅展示题型格式，正式生成时必须逐题核验：

```text
category: LYRICS
album: 我很忙
difficulty: EASY
question_text: 下列歌词短句出自哪首周杰伦歌曲？
option_a: 青花瓷
option_b: 兰亭序
option_c: 发如雪
option_d: 菊花台
correct_option: A
explanation: 该短歌词出自《青花瓷》，请以原版歌词页或专辑内页核验。
```

```text
category: LYRICS
album: 范特西
difficulty: MEDIUM
question_text: 《简单爱》中，给定歌词后紧接的下一句是哪一句？
option_a: 正确的相邻短句
option_b: 同专辑另一首歌的短句
option_c: 同一首歌但不相邻的短句
option_d: 相近年代歌曲的短句
correct_option: A
explanation: 正确答案是原版录音室版本中紧接在题干歌词之后的句子。
```

## 最终输出顺序

先输出中文统计：总题数、`LYRICS` 题目数、`EASY/MEDIUM/HARD` 数量、A/B/C/D 数量、专辑分布和待人工确认项。

最后输出 SQL：

```sql
-- 用途：导入已核验的周杰伦歌词题
-- 前置条件：question 表具有以下字段；影响表：question；幂等性：否，请在全量替换前清空旧题库
INSERT INTO question (
  category, album, difficulty, question_text,
  option_a, option_b, option_c, option_d,
  correct_option, explanation
) VALUES
('LYRICS', '专辑名', 'EASY', '题干', '选项 A', '选项 B', '选项 C', '选项 D', 'A', '简短解析');
```

SQL 规则：只有最后一行以分号结尾；单引号写为两个单引号；`NULL` 不加引号；每个 INSERT 必须对应至少一行“已核验”事实卡；“待人工确认”项不得生成 INSERT。
```
