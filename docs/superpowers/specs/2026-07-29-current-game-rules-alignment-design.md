# 当前游戏规则同步设计

## 目标

使前端离线降级结果、运行文档和游戏策略契约与当前配置保持一致；不修改排行榜查询、排序或历史成绩口径。

## 范围

1. 前端降级结果以当前 Round 的 `totalQuestions` 计算百分比分数与等级，不能假定每局 10 题。
2. 删除未被调用的 `GameStrategy.supportsRevival()` 契约及其深渊实现；保留深渊实际使用的 `revive()` 行为。
3. 更新 `ARCHITECTURE.md`、`PRD.md` 和 `TECH.md`：
   - 经典/专辑题量为当前配置的 20 题；经典题目组成使用 60% 简单、40% 中等的配置描述。
   - 专辑通关条件为 80% 正确率（当前为 16/20），不再写死 `8/10`。
   - 经典复活接口已移除；深渊续命为需登录的 `POST /api/abyss/revive`，首次错误且可续命时不返回答案和解析。
4. 不改排行榜 SQL、排名算法、历史记录、历史设计/计划文档和 UI 样例。

## 实现设计

- 将 `getLevelByScore` 改为接收答对题数和总题数，在内部先计算百分比，再以现有等级区间匹配；`finishAndSubmit` 调用时传入 `gameStore.totalQuestions`。
- 将 `calcScore` 的调用改为传入同一总题数，保持离线 `score` 在 0–100。
- 复活能力不再作为所有 `GameStrategy` 的通用可选能力；`AbyssController` 继续直接调用 `AbyssGameStrategy.revive()`。
- 文档使用“当前配置”描述运行规则，避免在接口路径中暴露已不再接受的 `count` 参数。

## 验证

1. 先新增前端测试：20 题答对 16 题的降级分数为 80，等级为 80% 对应等级；在现有代码下应失败。
2. 最小实现后运行该测试，再运行 `frontend` 的完整测试与构建。
3. 运行 `backend` 全量测试及 `admin` 构建。
4. 用文本检索确认三个运行文档不再包含旧的经典复活接口、20 题规则范围内的 `count=10` 或运行规则中的 `8/10`。

## 非目标

- 不规范化经典排行榜中历史 10 题与新 20 题记录的排序。
- 不修改数据库结构或迁移脚本。
