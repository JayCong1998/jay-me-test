# 认证表单校验与体验优化设计

## 目标

让登录与注册页面在输入时给出明确、可操作的校验反馈；服务端继续作为最终校验边界，并确保昵称不可重复。

## 校验规则

- 邮箱：必填，符合标准邮箱格式。
- 密码：必填，长度为 6–10 个字符。
- 昵称：必填，去除首尾空白后长度为 2–10 个字符；昵称在用户表中不可重复。
- 登录仅校验邮箱格式与密码长度；注册校验全部字段。

## 交互与错误处理

- 提交前和失焦后显示字段级提示；输入合法时给出简洁的正向状态。
- 提交按钮仅在表单合法且未提交时启用。
- 请求失败时，Axios 响应拦截器优先解析后端响应体中的 `msg`，再作为 `Error.message` 抛出；页面将该信息显示在表单顶部。例如邮箱格式错误显示“邮箱格式不正确”，不显示 HTTP 客户端默认错误文本。
- 后端通过 Bean Validation 处理格式与长度，通过 `AuthService` 在插入前处理邮箱和昵称重复；数据库增加昵称唯一约束，避免并发注册绕过应用层检查。

## UI

保留项目粉色渐变与移动端卡片风格，增加认证标签、输入框图标/状态区、明确的规则辅助文本、可见的聚焦状态与更紧凑的登录/注册切换入口。页面不引入新组件库。

## 测试

- 前端为纯校验函数覆盖合法与非法的邮箱、密码、昵称输入。
- 后端为注册服务覆盖重复昵称，以及 DTO 的规则边界。
- 前端 API 客户端覆盖非 2xx 响应体中业务错误消息的提取。
